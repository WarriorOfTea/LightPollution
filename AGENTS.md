# Работа с LightPollution

- Рабочая ветка — `main`: пользователь явно попросил перенести туда прежние
  результаты и продолжать без отдельных веток. Коммит и push связанных
  результатов разрешены постоянно; не переписывайте опубликованную историю.
- Текущий приоритет — данные, физическое ядро и проверяемые числа. Новую
  визуализацию глаза/камеры не выдавайте за достоверную до проверки калибровки.
  Геометрия Луны не равна её засветке, месячные источники — не готовый сезонный прогноз.
- Перед изменением модели читайте `THEORY.md`, `MODELS.md`, `LIMITS.md`
  и `docs/DATA_SOURCES.md`. Канонические документы находятся в корне:
  теория → выбранные модели → ограничения; изображения и внешний контроль —
  `VISUALIZATION.md`. Не создавайте параллельные пересказы этих документов.
- При каждом изменении кода, тестов и скриптов обновляйте
  `docs/CODE_CHANGELOG.md`: смысл, файлы, проверки, фактическое время
  завершения в ISO 8601 с секундами и смещением Europe/Berlin, статус реализации.
- Решения фиксируйте в соответствующем каноническом документе;
  текст ведите от первого лица автора проекта. `HISTORY.md` организуйте
  по этапам без дат, с результатами/изображениями. Даты правок остаются в журнале;
  численные отчёты, параметры, источники/права, QA, ограничения — в `artifacts/`.
  Не включайте секреты, большие временные скачивания и чужие материалы без прав.
- Проверки: `uv run pytest -q -p no:cacheprovider`, `uv lock --check`.
  Тесты не используют сеть и реальные токены. При повторе меняйте объём
  проверок только по новым изменениям или обнаруженным проблемам.
