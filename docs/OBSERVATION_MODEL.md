# Численная сцена наблюдения и однополосная модель лунной засветки
> Дата создания: 2026-11-10

Статус: реализованы первые три пункта последнего согласованного плана —
единая сцена, общая относительная шкала и лунный фон. Результат исследовательский;
независимая полевая точность не установлена. Калиброванное восприятие глазом,
модель камеры, сезонный масштаб и новый экранный рендер сюда не входят.

Код: `scene.py`, `photometry.py`, `moonlight.py`; геометрия — `observation.py`,
каталог/экстинкция — численные функции `skyview.py`, городской перенос —
`physics.py`. CLI: `lightpollution observe --scene INPUT.json --output DIR`.
Результаты и проверки: [отчёт этапа](../artifacts/observation-core-20261110/README.md).

## 1. Предмет расчёта и определения

Наблюдатель задаётся геодезической широтой, долготой и высотой. Направление
`ω=(A,h)` — азимут `A` от севера по часовой стрелке и высота `h` над местным
геометрическим горизонтом. Все входные углы — градусы; тригонометрические
функции в коде получают радианы.

Диффузный фон хранится отдельно от точечных звёзд. В одной принятой полосе V:

```text
Btotal(ω) = Bart(ω) + Bnatural(ω) + Bmoon(ω)
qk(ω) = Bk(ω) / Bref
qtotal(ω) = qart(ω) + qnatural(ω) + qmoon(ω)
```

Суперпозиция относится к линейным интенсивностям независимых источников.
Величины `q` безразмерны и имеют **одну общую опору**, не три независимые
нормировки. Опора задаётся поверхностной звёздной величиной `μref`:

```text
q = 10^[−0.4(μ−μref)]
μtotal = μref − 2.5 log10(qtotal), если qtotal>0
```

Это определение астрономической логарифмической шкалы, не модель ощущения
яркости. При нулевом компоненте его `q=0`; логарифм нуля не вычисляется.
JSON выдаёт `null` для отсутствующей конечной величины, не `Infinity/NaN`.

`KS_V_BAND` фиксирует эмпирическое V-соглашение Krisciunas–Schaefer (KS1991).
Численная кривая фильтра, спектральные функции CIE и QE камеры здесь не
импортированы. SQM, DNB, AB и отклик ночного глаза не подменяют эту полосу.
`RelativeBrightness` запрещает складывать разные полосы или опоры.

## 2. Контракт входной сцены

Корневой объект JSON имеет `schema_version=1`. Неизвестные ключи отвергаются.

| Поле | Формальное содержание |
|---|---|
| `mode` | `dated` либо `undated`; текущая дата автоматически не подставляется. |
| `observer` | Обязательные `latitude_deg∈[−90,90]`, `longitude_deg∈[−180,180]`, `height_m∈[0,80000)`; высота также ниже верха атмосферы. |
| `directions` | Непустой список `[A,h]`; конечный азимут приводится по модулю 360; `h∈[0,90]`. |
| `cloud_free` | По умолчанию `true`; `false` пока не поддерживается. |
| `atmosphere` | Параметры существующего класса `Atmosphere`; пропуски получают явно экспортируемые значения по умолчанию. Опорная длина волны строго 550 нм. |
| `reference_v_mag_arcsec2` | Конечная `μref`, по умолчанию 22; это единица сравнения, не измеренный естественный фон. |
| `natural` | Явный сценарий `uniform` с `v_mag_arcsec2` и `source` либо `none` с причиной в `source`. |
| `artificial` | Явное `none` либо сохранённое поле `grid` с привязкой масштаба, происхождением и описанием спектрального приближения. |

### Датированный режим

Обязателен `time`: ISO 8601 с датой, часом и часовым поясом; например,
`2025-01-13T00:00:00+03:00`. Он нормализуется в `2025-01-12T21:00:00Z`.
Ручное поле `moon` запрещено: положение, фаза и расстояние берутся из эфемерид.
Используются Astropy builtin и локальные IERS-таблицы без сетевой загрузки.

Рефракция выключена. Координатные преобразования используют WGS84, городской
перенос — сферу радиуса 6371 км; это существующее геометрическое приближение.
При высоте центра Солнца выше −18° расчёт сцены отвергается: сумеречная
составляющая ещё не реализована. Будущие эфемериды не предсказывают будущие
аэрозоли или включение фонарей: эти входы остаются сценариями.

### Условный режим без даты

Поле `time` запрещено. Обязателен `moon`: `{"mode":"none"}` либо
`mode=manual` с конечными `azimuth_deg`, `altitude_deg∈[−90,90]`,
`phase_angle_deg∈[0,180]`. Расстояние положительно, по умолчанию 384400 км.
Такой ввод описывает идеализированную геометрию, не удостоверяет существование
соответствующей ясной ночи. Затмение предполагается отсутствующим.
Положения звёзд не назначаются; CSV звёзд содержит только заголовок.

## 3. Физика атмосферы и согласование V с текущим ядром

Действующее городское ядро считает однократное молекулярное/аэрозольное
рассеяние, поглощение и ослабление на обоих участках. Его нормированные
источники из VIIRS не являются измеренной мощностью городов в V.
Полный вывод — [MODEL.md](MODEL.md).

В этой версии **форма** поля на условных 550 нм используется как форма
эффективного V-поля, а масштаб задаётся в V отдельно. Это серое приближение,
не равенство монохроматического сигнала и интеграла по реальному фильтру.
Неизвестные спектры и спектрально-зависимое угловое рассеяние оставляют
ошибку формы; один калибровочный коэффициент её не устраняет.

Для высоты `z` над сферической поверхностью профили прежнего ядра:

```text
βR(z) = βR,0 exp(−z/HR)
βa,e(z) = (τa/Ha) exp(−z/Ha)
βe(z) = βR(z)+βa,e(z)                 [м⁻¹]
T = exp(−∫ βe ds)
```

Последняя формула — закон Бугера–Ламберта–Бера. Вертикальная оптическая
толщина между высотой наблюдателя `z0` и верхом атмосферы `H` интегрируется
аналитически. Через определение звёздной величины получаем:

```text
τvertical = βR,0 HR [exp(−z0/HR)−exp(−H/HR)]
          + τa [exp(−z0/Ha)−exp(−H/Ha)]
kV = (2.5/ln 10) τvertical           [mag / airmass]
```

`kV` для Луны выводится из той же заданной атмосферы при указанном сером
приближении. Дополнительная независимая ручная экстинкция не вводится.
Модель KS имеет фиксированную эмпирическую угловую функцию: изменение `g`
или альбедо аэрозоля не перестраивает её так, как полный спектральный решатель.
Поэтому это согласование экстинкции, а не полное равенство двух моделей переноса.

### Привязка городского поля

Пусть `R(ω)` — ненормированный отклик сохранённого решателя, `ωa` — опорное
направление, `μa` — заданная искусственная яркость только этого направления:

```text
qart(ω) = [R(ω)/R(ωa)] × 10^[−0.4(μa−μref)]
```

Требуются `R(ωa)>0`, покрытие направления сеткой и единственное значение
зенита. Проверяются точное совпадение наблюдателя/атмосферы с метаданными
NPZ и SHA-256 входа. Интерполяция периодическая билинейная в линейном свете,
без экстраполяции по высоте. Масштабирование всего `R` на одну константу
сокращается, но отношение Луны и города сохраняется благодаря общей опоре.

`scale_origin=scenario` означает допущение. `provided_calibration` означает
предоставленную извне калибровку с обязательной ссылкой `source`; программа
не удостоверяет её качество. В обоих случаях независимая полевая проверка
не объявляется выполненной. Текущие опыты используют **сценарий** 20,5
V mag/arcsec² искусственного зенита, как прежний прототип.

## 4. Однополосная модель Луны

Основание: [Krisciunas & Schaefer, 1991](https://doi.org/10.1086/132921),
[оригинальный текст](https://articles.adsabs.harvard.edu/pdf/1991PASP..103.1033K).
Независимое опубликованное вычисление для сравнения —
[specsim, krisciunas_schaefer](https://specsim.readthedocs.io/en/stable/_modules/specsim/atmosphere.html).

### Геометрия и фазовая яркость

`α` — угол Солнце–Луна–центр Земли: 0° соответствует полнолунию, 180° —
новолунию. Приближение освещённой доли `f=(1+cos α)/2` описывает геометрию
диска. Для потока используется отдельная эмпирическая зависимость:

```text
mMoon(α) = −12.73 + 0.026 α + 4×10⁻⁹ α⁴
I* = 10^[−0.4(mMoon+16.57)] × (d0/d)²
d0 = 384400 км
```

`I*` соответствует освещённости вне атмосферы в соглашении статьи.
Множитель `(d0/d)²` — добавленное нами приближение из закона обратных
квадратов; оригинальная базовая формула расстояние не корректирует.
Для табличной проверки ставим `d=d0` и точно получаем исходную модель.
Изменение расстояния до Солнца и деталей отражения лунной поверхности здесь
не рассчитывается. Используется геоцентрическая фаза и топоцентрическое
расстояние; полный лунный BRDF не восстанавливается.

### Атмосферное рассеяние и ослабление

`ρ` — угловое разделение Луны и участка неба, `hM` и `h` — их высоты.
Разделение вычисляется сферическим скалярным произведением. Для `ρ≥10°`:

```text
X(h) = [1−0.96 cos²(h)]^(−1/2)
Fscatter(ρ) = 10^5.36 [1.06+cos²(ρ)] + 10^(6.15−ρ/40)
BMoon,nL = Fscatter(ρ) I* 10^[−0.4 kV X(hM)] {1−10^[−0.4 kV X(h)]}
```

Первая составляющая `Fscatter` имеет рэлеевскую угловую форму; вторая —
эмпирический аэрозольный вклад, а не численное решение теории Ми. Коэффициенты
включают нормировки/единицы и подгонку: эту функцию нельзя считать
нормированной на единицу фазовой функцией `p(θ)` прежнего ядра.

Множитель пропускания отражает ослабление света Луны, скобка — накопление
рассеянного вклада вдоль направления. `X` — специальная «масса рассеяния»
KS, равная 1 в зените и 5 на горизонте; это не прямолучевая воздушная масса.
Для малых оптических толщин скобка вычисляется через `expm1`, чтобы избежать
вычитания близких чисел. При `kV=0` получается нулевой рассеянный фон.

Переход из численной шкалы статьи в её поверхностную V-величину:

```text
BV,nL = 34.08 exp(20.7233−0.92104 μV)
μMoon = [20.7233−ln(BMoon,nL/34.08)] / 0.92104
qmoon = 10^[−0.4(μMoon−μref)]
```

Округлённые коэффициенты сохранены для воспроизводимости статьи. Эти nL
используются внутри эмпирического V-соглашения; универсального перевода
произвольного спектра или SQM в фотопические кд/м² программа не делает.

## 5. Маски и границы применимости

- При `ρ<10°` и Луне над горизонтом лунный и суммарный фон равны `null`;
  городской/естественный компоненты сохраняются. Диск, ближний ореол, блики
  глаза и объектива не заменяются нулём и не изображаются.
- При центре Луны на/ниже горизонта её фон принят нулевым с явным предупреждением:
  остаточное освещение высокой атмосферы не моделируется.
- При `α<7°` ставится предупреждение об отсутствии оппозиционного усиления.
  Полная фазовая BRDF и точное околополнолунное усиление не реализованы.
- В датированном режиме возможное затмение выделяется консервативным
  геометрическим условием `α<asin(RE/dM)+asin(RSun/dMS)+asin(RMoon/dM)`.
  Радиусы 6378,137 / 695700 / 1737,4 км. Это приблизительный экран возможной
  полутени с запасом на лунный радиус, не точный календарь контактов.
  При положительной отметке и видимой Луне лунный/суммарный фон неизвестен.
- Высоты ниже 10° получают предупреждение: нет рефракции, рельефа и точной
  низкой атмосферы. Формула не объявляется одинаково точной по всему куполу.
- Естественный фон сейчас однородный сценарий; airglow, Млечный Путь,
  зодиакальный свет и сумерки раздельно ещё не вычисляются.

Контекст `observation_context` по-прежнему описывает только геометрию и
помечает отсутствие радиометрии **в этом контексте**. Отдельная команда
`observe` использует геометрию для описанного здесь расчёта света.

## 6. Звёзды и различие потока/фоновой яркости

При известном UTC BSC5 даёт направления и каталожные V-величины. Существующие
преобразования FK5 J2000 и собственных движений используются повторно.
Прямолучевая экстинкция получается сферической квадратурой существующего
профиля до верха атмосферы, не через приближённое `X` лунной модели:

```text
τstar = ∫луч βe ds
Δmstar = (2.5/ln 10) τstar
mobserver = mcatalogue + Δmstar
Fobserver/F0,V = 10^(−0.4 mobserver)
```

Сохраняются звёзды над геометрическим горизонтом в высотном покрытии сетки.
Это не список звёзд, обнаружимых глазом. Поток относительно V=0 хранится
отдельно от `B/Bref`; их прямое сложение запрещено смыслом единиц.
Для сравнения с фоном нужна угловая апертура `Ω` и фон `∫Ω B dΩ`, а для
звезды — соответствующая доля потока. Такой наблюдательный модуль отложен.

## 7. Выход и воспроизводимость

`observation.json` содержит нормализованное UTC либо `null`, исходную сцену,
эффективные параметры, полосу/опору, ограничения, SHA-256 и метаданные поля,
геометрию и значения направлений. `directions.csv` содержит отдельные `q`
и суммарную величину с маской `supported/status`. `stars.csv` — положения,
величины, экстинкцию и относительные потоки, без рендера и порога видимости.

Полный пример входа:
[с датой](../artifacts/observation-core-20261110/dated-2025.scene.json),
[без даты](../artifacts/observation-core-20261110/undated-phase-60.scene.json).
Пути сеток разрешаются относительно JSON-файла. Повторная запись результата
без даты создаёт пустой CSV звёзд с заголовком и не оставляет прежний каталог.
CSV используют фиксированный LF для сохранения контрольных сумм после Git checkout.

Автотесты проверяют опубликованные числа, предельные случаи, общую шкалу,
совпадение ручной/эфемеридной геометрии, маски и ошибки входов. Семь
воспроизводимых случаев выполняет `scripts/run_observation_cases.py`.
Полевой процент ошибки отсутствует: неизвестные спектры, реальная атмосфера,
источники ближе 3 км и за окном карты остаются существенными ограничениями.
