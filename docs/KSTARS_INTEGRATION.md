# Нативная интеграция LightPollution в KStars
> Дата создания: 2026-11-11

Дополнение 0.7: нативное окно загружает `eye-preview.png`, рассчитанный
при ширине 900 px, и показывает пиксели без `QPixmap::scaled`. Это устраняет
повторное уменьшение уже кодированных звёзд. Исходная карта KStars
сохраняет свои глифы. Обновлённая Qt5-сборка/две реальные задачи проверены
[отдельно для 0.7](../artifacts/eye-rendering-20261111/native/native-verification.json).
Qt6/HiDPI и личная экранная калибровка остаются непроверенными.


Дополнение 0.6: панель имеет переключатель ограниченного порога глаза и
кнопку просмотра рассчитанного PNG в собственном Qt-окне. Сигнал и фон
вычисляет тот же backend. D-Bus `showEyeView()` запускает загрузку экспорта;
`statusJSON()` сообщает `eye_display` и `eye_preview_ready`. Исходная карта
KStars не заменяется этим изображением. Область/формулы:
[EYE_MODEL.md](EYE_MODEL.md); проверка `check_kstars_native.py --eye`.

Статус реализации и протокол запуска — в
[отчёте](../artifacts/kstars-terrain-near-20261111/README.md).
KStars 3.6.2 действительно собран и запущен: 2/2 холодных и 2/2 повторных
расчёта, геометрия/UTC/устаревание/AGL–MSL и снимки окна проверены.
Проверочная Linux/Qt5-сборка отключает INDI/Ekos device control.
Модуль находится в `integrations/kstars/`; вычислительное ядро остаётся
самостоятельным Python-пакетом. Сайт — дополнительный локальный клиент того
же ядра, не механизм встраивания панели в KStars.

## 1. Зачем разделены программа и модели

Теория: геометрическое состояние планетария и вычисленная радиансность —
разные величины. Дата и координаты задают направления объектов, а атмосфера,
источники и поверхность задают распространяющийся свет. Чтобы изменять эти
части независимо, нужен снимок состояния с явными единицами и соглашениями.

Проблема: прежний запуск `--dump` давал картинку каталога и внешнее наложение;
внутри программы не было нашей панели. Последовательное чтение места,
времени и направления через разные внешние вызовы также может захватить
разные моменты движущейся карты. Высота города над морем не равна высоте глаза.

Решение: нативная C++/Qt-панель работает внутри KStars. Один вызов в потоке
интерфейса снимает геометрию и отправляет JSON в локальный расчётный процесс.
Новые физические модели используют тот же контракт и не требуют переписывать
карту или каталоги. Развитие моделей и интеграции возможно одновременно;
отдельно проверяется совместимость единиц, датумов и версий.

## 2. Что полезного есть в KStars и что используется

Аудит текущего исходного кода закреплён commit
`50e6b7b70078da6107616671b019f0eccbca1266`; проверяемая сборка выбрана
отдельно из исходников KStars 3.6.2. Проверка старой версии не доказывает
сборку на текущем Qt6/master. Установленный пользователем системный KStars
автоматически не изменяется; публикация в upstream KDE не выполняется.

| Данные/алгоритм KStars | Применение и статус |
|---|---|
| GeoLocation: широта, долгота, высота, название места | Панель читает штатный объект; широта/долгота — вход модели, MSL-высота сохраняется справочно. При DSM модель берёт высоту поверхности из него. AGL задаётся отдельно. |
| SimClock, KStarsData::ut | UTC берётся из виртуального времени программы, включая будущую дату/паузу. Системные часы не подменяют выбранную дату. |
| SkyMap focus, SkyPoint: az/alt, RA/Dec, FOV | Читается центр карты и его геометрическая высота `alt()`. RA/Dec текущей эпохи и FOV сохраняются для происхождения/будущего поля. Запрошенный физический луч совпадает с центром карты. |
| SkyPoint refraction/unrefraction | Алгоритм уже есть. Snapshot помечен `geometric_unrefracted`; `altRefracted()` повторно не передаётся как геометрическая высота. Переход к воспринимаемому положению отдельный. |
| Каталоги и focusObject::mag/name | Панель сохраняет имя/каталожную величину выбранного объекта. Масштаб отрисованного кружка не используется как физический поток. Поле звёзд ядро пока считает по BSC, полного переноса всех каталогов KStars нет. |
| StarObject, getObjectDataXML: B−V, спектральный тип, HD, собственное движение, параллакс | B−V/тип/HD выбранной звезды добавлены в snapshot; служебное 99,9 для отсутствующего B−V превращается в null. Собственное движение/параллакс доступны для следующего каталожного адаптера. B−V не является измеренным полным спектром. Автоматическая замена BSC этими данными пока не выполняется. |
| ArtificialHorizon::isVisible | Нативно переиспользуется маска активных пользовательских областей, включая потолочные ограничения, для выбранного направления. Закрытое направление не выдаёт фиктивную сумму неба. |
| TerrainComponent | Имеется панорамное изображение местности. Оно не содержит метрические DSM-высоты всех источников и не заменяет расчёт двух путей заслонения. Панорама не обращается в DEM. |
| D-Bus KStars и SimClock | Используются в проверке живого приложения: изменение места/даты/направления и считывание нашего атомарного снимка. Добавлен наш интерфейс `/LightPollution`. |
| Ekos Exposure Calculator | Уже учитывает заданную яркость неба, свойства камеры и шумы; не следует утверждать, что фон отсутствует. Наша будущая роль — дать направленно/временно зависимый отклик в нужной полосе, затем проверить перевод в электроны. Автоподстановка в Ekos пока не реализована. |
| INDI CCD Simulator / SkyGlow | Уже существует приближённый sky-glow. Не является независимым доказательством радиометрической точности или вида глазом. Этот модуль не переписан. |

Ранее подробный разбор симулятора и калькулятора:
[KSTARS_CAMERA_AUDIT.md](KSTARS_CAMERA_AUDIT.md).
Не извлекаются из внешнего вида карты спектр звезды, физическая яркость
препятствия или реальная мощность местного фонаря.
В проверенной поставке 3.6.2 для Веги доступны HD 172167 и тип A0, но
`getBVIndex()` возвращает отсутствие B−V; snapshot сохраняет `null`.
Наличие поля/алгоритма в программе не означает полноту данных каталога.

## 3. Контракт и управление задачами

`LightPollutionDock` — `QDockWidget` главного окна, с пунктом меню и
параметрами периода источников, DSM, AGL, AOD, ближних ячеек и спектра.
Можно открыть полный `scene.json`; остальные физические параметры сохраняются.

Атомарный snapshot версии 1 включает:

```json
{
  "schema_version": 1,
  "kstars_version": "3.6.2",
  "utc": "2026-11-11T21:00:00Z",
  "altitude_convention": "geometric_unrefracted",
  "location": {"latitude_deg": 60.3, "longitude_deg": 30.315, "elevation_m": 20},
  "focus": {"azimuth_deg": 180, "altitude_deg": 45},
  "artificial_horizon_visible": true
}
```

`POST /api/kstars/jobs` получает `{scene, snapshot}`. Строгий адаптер
подменяет ручные место/UTC/направление данными KStars, сохраняет AGL и другие
параметры модели, исключает ручную Луну и считает эфемериды для даты.
Высота места хранится в provenance, SHA snapshot — в сцене; исходный
снимок сохраняется по ID задания. Отсутствующая временная зона,
рефрагированная высота, NaN, bool вместо угла и неверная схема отвергаются.

Расчёт выполняет прежняя очередь отдельных процессов; GUI не блокируется.
Панель опрашивает статус, показывает известные составляющие и `—` для `null`,
сохраняет полный результат. Отмена проверяется между расчётными лучами:
она не прерывает отдельный NumPy-интеграл мгновенно. Сетевые обращения
ограничены 15 с, сами задания могут выполняться дольше.

Смена геометрии/параметров помечает результат устаревшим. Автослежение —
явный переключатель, по умолчанию выключен. Для запуска изменений используются
кванты 0,25° и 60 с и пауза стабильности; в вычисление уходит фактический
полный snapshot, а не округлённые углы. Одновременно работает одно задание;
при новом состоянии старое отменяется и результат не объявляется текущим.
Ключ вычислительного кэша содержит точные параметры, поэтому округление
интерфейса не подменяет физическую геометрию.

Панель обращается только к loopback HTTP `LIGHTPOLLUTION_URL`, по умолчанию
`http://127.0.0.1:8765`. Это локальный исследовательский режим без сетевого
развёртывания/авторизации. Сервис не следует открывать в публичную сеть.
Для CLI `kstars-snapshot` нужен дополнительный пакет `dbus-next` (`--extra kstars`).

Добавленный D-Bus интерфейс `org.lightpollution.KStars`, путь `/LightPollution`:
`snapshotJSON`, `setSceneJSON`, `calculate`, `statusJSON`, `savePanelScreenshot`,
`saveWindowScreenshot`.
Он использует существующий session service `org.kde.kstars`; отдельный
сервер не присваивает имя KStars. Скриншот снимается самой Qt-панелью,
не генерируется как макет.

## 4. Сборка и запуск

Исходники модуля GPL-2.0-or-later совместимы с KStars. Репозиторий не содержит
изменённую многосотмегабайтную копию KStars. Идемпотентный скрипт проверяет
ожидаемую структуру исходников и добавляет исходник/панель/пункт меню:

```bash
uv sync --extra terrain --extra kstars
uv run python integrations/kstars/apply_native.py --source /path/to/kstars-source
cmake -S /path/to/kstars-source -B /path/to/kstars-build -DBUILD_TESTING=OFF
cmake --build /path/to/kstars-build --target kstars -j2

uv run lightpollution prepare-terrain --dataset petersburg-copdem90 --directory data/terrain
uv run lightpollution serve --host 127.0.0.1 --port 8765
LIGHTPOLLUTION_URL=http://127.0.0.1:8765 /path/to/kstars-build/bin/kstars
```

Требуются штатные C++/Qt/KDE зависимости выбранной версии KStars.
Python `rasterio` нужен для подготовки GeoTIFF, но не для чтения готового NPZ.
Конкретные закреплённые исходники, способ изолированной сборки и результат
нашей проверки записаны в отчёте; это не инструкция устанавливать старую
версию поверх пользовательской. В обычной среде панель доступна из меню;
при установленной `LIGHTPOLLUTION_URL` показывается при старте.

## 5. Что остаётся

- Проверить/адаптировать native-модуль на актуальном KStars Qt6, собрать
  воспроизводимый пакет под выбранную ОС и обсудить upstream-включение.
- Передать не только центр карты, но и угловую сетку FOV с допуском на
  интерполяцию; использовать каталожные идентификаторы KStars без двойных
  звёзд, проверить собственные движения/системы координат.
- Вставить спектрально корректный фон в Ekos/INDI после согласования полос,
  апертуры, QE, пикселей, экспозиции и шума. Сейчас численная панель ничего
  автоматически не меняет в симуляторе снимков.
- Добавить детальные локальные препятствия и известные лампы. Пользовательская
  маска горизонта закрывает луч, но не описывает городское светораспределение.
- После наземной проверки шкалы — модель обнаружения глазом и камеры.
  Ни эта панель, ни старый внешний overlay не являются таким результатом.
