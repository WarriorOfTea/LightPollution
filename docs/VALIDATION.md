# Проверка моделей и независимые наблюдения
> Дата создания: 2026-11-12

Я разделяю проверку программы и проверку реального мира. Этот документ
задаёт их порядок, данные и метрики. Предельные условия моделей находятся
в [LIMITS](../LIMITS.md), а правила сравнения изображений — в
[VISUALIZATION](../VISUALIZATION.md).

## 1. Четыре уровня проверки

| Уровень | Что проверяю | Чего он не доказывает |
|---|---|---|
| Аналитический | Единицы, баланс энергии, нормировки, известные пределы | Совпадение сценария с реальной ночью |
| Программный | Формулы литературы, контракты, маски, хеши, экспорты | Полноту физической модели |
| Численный | Сходимость квадратуры, размер ячеек, независимые лучи | Малую ошибку от пропущенного физического процесса |
| Наблюдательный | Независимые ночи/места/сенсоры/люди | Универсальную переносимость за пределы выборки |

Фон и источники сравниваю в одинаковой полосе и линейных величинах.
Квадратуру уточняю при фиксированном C. Прямые heldout-лучи не использую
для адаптации интерполяции; указываю число поддержанных/запрошенных направлений.

## 2. Калибровка общего городского масштаба

Настраиваю один положительный C при фиксированных атмосфере, форме
источников и прочем фоне. Ясность требует указанного источника погодного QA;
одно тёмное значение или положение Солнца её не подтверждает.
Строгий первый fit использует Солнце≤−18°, Луну≤−5° и standard-профиль.

Разделяю целые ночи, в том числе между станциями. Средние считаю
в линейном свете; каждая ночь получает одинаковый суммарный вес.
Контрольные bias/MAE/RMSE сопровождаю единицами, количеством измерений,
ночей, групп направлений и независимых площадок.

Для остатка ei=μmodel,i−μobserved,i:

```text
bias=Σei/N; MAE=Σ|ei|/N; RMSE=sqrt(Σei²/N).
```

Совпадение среднего обучения по одному коэффициенту не является точностью.
В существующем мадридском опыте есть отдельная ночь контроля, но нет
доказанной пространственной переносимости. Хеш файла защищает от порчи,
не удостоверяет качество измерений. Несовместимая область fit отклоняется.

## 3. Что нужно для проверки глаза

Режим 0.8/0.9 подготовлен к импорту, но независимых наблюдателей/ночей 0.
Синтетические метки тестов не включаю в статистику людей.

До знакомства с ответом модели фиксирую место/UTC/AGL, ясность, горизонт,
прозрачность и световые условия. Записываю анонимный observer_id,
коррекцию зрения, длительность адаптации и одинаковую процедуру поиска.
Для пилота использую ориентир 30 минут без яркого экрана; importer
отклоняет<20 минут. Такой фильтр не доказывает адаптацию конкретного глаза.

Заранее выбираю разные q, включая невидимые звёзды, перемешиваю порядок
и сохраняю отрицательные ответы. `seen` и `colour_label` — разные ответы.
Фото/догадка по каталогу не заменяют наблюдение. Контрольные ночи отделяю
до подбора параметров; повторные попытки оформляю собственным протоколом.

Для экранного изображения дополнительно нужны black/white, угловая
геометрия окна, расстояние, освещение помещения/профиль ОС. Для полного
спектрального зрения — первичные спектры дисплея. Переданный через Telegram
PNG с неизвестными условиями остаётся иллюстрацией.

## 4. Формат наблюдений и импорт

[Пустой шаблон](../artifacts/eye-colour-20261111/observation-template.json)
даёт `prepared_not_observed`, observers0/nights0. Следующий JSON показывает
структуру; пути/хеш заменяются реальными данными:

```json
{
  "schema_version": 1,
  "kind": "eye_observations",
  "cases": [{
    "id": "site-night-a",
    "night_id": "night-a",
    "result_path": "relative/path/to/result.json",
    "result_sha256": "REPLACE_WITH_ACTUAL_LOWERCASE_SHA256_OF_RESULT_FILE",
    "conditions": {
      "clouds": "clear",
      "adaptation_minutes": 30,
      "direct_lamps_visible": false
    }
  }],
  "observations": [{
    "case_id": "site-night-a", "observer_id": "anonymous-001",
    "hr": 7001, "seen": true, "split": "calibration", "colour_label": null
  }]
}
```

Путь разрешается относительно набора; проверяю SHA-256 результата
и присутствие HR в физической eye-таблице. Неподдерживаемые условия
исключаю с подсчётом, не превращаю в `seen=false`. Дубликаты
observer/case/star, неверные boolean и утечка ночей вызывают ошибку.
Цветовые метки: null/white/red/orange/yellow/blue/uncertain; они пока
не образуют валидированную цветовую классификацию.

```bash
uv run python scripts/audit_eye_observations.py \
  artifacts/eye-colour-20261111/observation-template.json \
  --output scratch/observation-status.json
```

Я не считаю importer проверкой подлинности ответов. Рабочие персональные
данные автоматически в Git не публикуются; для проекта достаточно
обезличенных записей/агрегатов.

## 5. Подбор F и метрики зрения

При сохранённом F0 и q0 величина b=q0F0 не зависит от нового F.
Предсказание: b/F≥1. По calibration-записям данного наблюдателя
подбираю F∈[0,5;10] по balanced accuracy; нужны обе категории.
Перебираю точки смены решений, промежутки и номинальный F2.
При равенстве выбираю ближайшее в logF к медиане прежних F.

Calibration/validation не могут разделять ни night_id, ни SHA исходного
расчёта, даже для разных наблюдателей. Сохраняю TP/TN/FP/FN и знаменатели:

```text
Nseen=TP+FN; Nnot_seen=TN+FP; N=их сумма;
sensitivity=TP/Nseen; specificity=TN/Nnot_seen;
accuracy=(TP+TN)/N;
balanced_accuracy=(sensitivity+specificity)/2.
```

Метрики выдаю также по наблюдателям/ночам. При нулевом знаменателе
величина неизвестна; недостаточное обучение даёт F=null. F может поглотить
ошибку фона/атмосферы и не должен автоматически считаться свойством глаза.
Звёзды одной ночи коррелированы: для будущих интервалов потребуется
кластерный bootstrap по ночам, а не псевдонезависимые тысячи звёзд.
Такой полный статистический эксперимент пока не выполнен.

## 6. Проверка реальной камеры: следующий протокол

Сейчас я проверяю формулы и синтетический FITS, а не реальные RAW.
Автоматический полный импорт/fit реального сенсора ещё не реализован.
Для независимой кампании планирую:

1. Закрепить одну камеру/режим, QE и фильтр, g/RN/fullwell, температуру,
   оптику, выдержку и отсутствие нелинейной обработки.
2. Получить bias/dark/flat и линейные RAW, маски дефектов и насыщения.
3. Установить геометрию/WCS, согласованный каталог и угловые маски.
4. Измерить фон и звёздные потоки в согласованной полосе; сравнить
   электронные средние/дисперсии и зависимость от выдержки.
5. Настраивать параметры на отдельных ночах, проверять на других;
   сохранять остатки/маски/метрики, включая неудачные случаи.

В уже выполненном синтетическом контроле 614400 ADU совпали при повторе,
10/10 HDU прошли checksum, Monte Carlo200000 проверил заданные среднее
и дисперсию. Это проверка реализации модели. Её нельзя выдавать
за перечисленную выше наблюдательную кампанию.

## 7. Нативный каталог, Ekos и маска

В проверке0.10 я использую реальную Qt6-сборку. Фиксирую установленные
хеши, место/UTC/AGL, три ракурса/маски и seed камеры. Повторяю каталог
после другого ракурса и цикла рисования; сравниваю все ID/V/B−V/астрометрию,
не только количество. Три слабых HD проверяю через штатный поиск.

Штатный калькулятор Ekos сравниваю с независимой скалярной формулой
при том же RN и b в e⁻/pixel/s. Проверяю отсутствие повторного QE/f-ratio
и отсутствие автоматического изменения устройств/Capture. Контуры/потолки
сравниваю с native isVisible на2054 направлениях, включая границы/север.

Замороженный вход хранит полный integration вместе с линейным светом,
сенсором и seed. Для зенита и частичного горизонта воспроизведены
по614400/614400 ADU, MASK и MEAN_E/SKY_E/STAR_E; проверены NaN/0 за маской
и по10/10 FITS checksum. Отдельно повторён прежний311-звёздный вход.
Ожидаемый ошибочный запрос должен оставить прежний результат устаревшим.
Это не независимые RAW или наблюдения людей: их новых0.
[Полный протокол](../artifacts/kstars-catalogue-integration-20261112/README.md).
