# Атмосфера, месячные источники и наземный контроль: отчёт этапов 4–6
> Дата создания: 2026-11-10

> Я сохраняю этот отчёт как архив конкретного опыта. Его статусы относятся к описанной версии; текущее устройство — в [MODELS](../../MODELS.md), ход развития — в [HISTORY](../../HISTORY.md).

Выполнены ручные параметры атмосферы, сезонное сопоставление источников
на общей области и первый ограниченный наземный контроль. Подготовлен
каталог 65 факторов для выбора дальнейших приоритетов. Новые изображения
неба не создавались: выход этого этапа — численные поля, проверки и документация.

## 1. Что работает и как

### Атмосфера: этап 4

Параметры можно задавать в `atmosphere` JSON-сцены или отдельным файлом
`simulate --atmosphere-file`. Команда `atmosphere --output PATH` экспортирует
все восемь исходных значений. `--aod` явно переопределяет только AOD.
Пропущенные поля дополняются; ошибочные ключи, нечисловые и нефизические
значения отклоняются. Одинаковые параметры используются для городского
переноса, ослабления звёзд и эффективной экстинкции лунной модели.

| Параметр | Значение по умолчанию |
|---|---|
| Условная длина волны | 550 нм |
| Молекулярная масштабная высота | 8000 м |
| Аэрозольная масштабная высота | 1200 м |
| Вертикальная аэрозольная оптическая толщина AOD | 0,10 |
| Альбедо однократного рассеяния аэрозолей | 0,9 |
| Асимметрия HG `g` | 0,8 |
| Множитель молекулярного рассеяния | 1 |
| Верхняя граница интегрирования | 80 км |

Это базовый правдоподобный ясный сценарий, выбранный для сопоставимости
с прежним ядром. Он **не оценён как наиболее вероятная погода конкретного
места и сезона**. `atmosphere_origin` перечисляет заданные и подставленные
поля, `measured_weather=false`, `regional_probability_estimated=false`.
Восстановление реальной атмосферы и сбор рядов отложены по решению пользователя.

### Сезонность и проверка: этап 5

`prepare-seasonal` объединяет месячные VNP46A3.002 на одной маске,
сохраняет отношение амплитуд и запрещает несовместимые выборки.
`select-ground` отбирает геометрические кандидаты AstMon Johnson V.
`fit-ground` отделяет настройку масштаба от проверки других ночей;
неизвестная облачность требует явного предварительного режима.
`observe` умеет использовать общую V-опору другого месяца, чтобы не стереть
сезонное изменение повторной нормировкой.

### Общая система, включая прежние этапы

| Часть | Фактическая реализация |
|---|---|
| Городское свечение | Однократное рассеяние Рэлея и Хеньи—Гринстейна, экспоненциальная атмосфера, поглощение аэрозолями, ослабление на обоих путях, непрозрачная сферическая Земля. |
| Источники | Принятые по QA радиансности VIIRS, площади ячеек, сценарная угловая диаграмма; относительная мощность, без абсолютной спутниковой инверсии. |
| Звёзды | 9096 записей BSC5, координаты/собственные движения и геометрия Astropy для места и UTC, атмосферная экстинкция. |
| Луна | Эмпирическая модель Krisciunas–Schaefer 1991 в эффективной V: фаза, положение, угол до цели, расстояние и ослабление. Ближние 10° и возможные затмения маскируются. |
| Общая шкала | Раздельные городская, лунная и естественная составляющие складываются в линейных единицах относительно одной V-опоры. Спектральный переход городского 550-нм поля остаётся приближением. |
| Время | Датированные сцены с геометрией и условные сцены без даты. Сумеречные сцены отклоняются: одного расчёта положения Солнца недостаточно для сумеречного фона. |
| Глаз, камера, KStars | Сохранены прежний условный рендер и внешний слой KStars. Физиологическая модель, физический сенсор и встроенные кнопки не реализованы. |

## 2. Теория и математические решения

Для ячейки `i` и месяца `m`: `Dm,i` — исправленная DNB-радиансность,
`Ai` — площадь, `M` — общая маска всех месяцев. Маска требует конечного
неотрицательного DNB, `Quality=0`, `Num>3`, принятой суши/берега и расстояния
от наблюдателя не менее 3 км. Вода исключена. Ноль при хорошем QA допустим;
непригодное измерение не подменяется нулевым светом.

```text
Sm = Σi Mi Dm,i Ai
Pproxy,m,i = Mi Dm,i Ai / Sreference
Rm(ω) = Σi Ki(ω; atmosphere) Pproxy,m,i
qart,m(ω) = Rm(ω)/Rreference(ωanchor) × qanchor,reference
```

`K` — прежний отклик переноса. Уравнение линейно по мощности при фиксированной
атмосфере; поэтому множитель `Sm/Sreference` сохраняет межмесячную амплитуду.
Независимая нормировка каждого месяца на его собственный зенит уничтожила
бы это изменение. Новая привязка проверяет опору, наблюдателя, атмосферу,
композит и SHA-256 общей маски. Она необходима и при равенстве суммарных
амплитуд: пространственная перестройка источников всё равно меняет небо.

Порог покрытия 80% принят как рабочее правило пригодности данных,
не как доверительный уровень. Допущение о постоянном переходе DNB-to-V
и угловой диаграмме между месяцами ещё требует проверки. Спутниковая
лунная/атмосферная коррекция не заменяет наземный перенос света.

Наземные величины сначала переводятся в линейную шкалу и усредняются
внутри локальной ночи. Каждая ночь имеет одинаковый вес. Опора `μref=22`,
естественный фон `μN=21,6` V mag/arcsec² фиксирован сценарием.

```text
bi = 10^[−0.4(μi−μref)]
bn = mean_i_in_night(bi)
xn = Rmonth(zenith) / Rreference(zenith)
bn,predicted = a xn + bN
a = Σtrain[xn (bn−bN)] / Σtrain[xn²]
```

Это минимум суммы квадратов линейных остатков по одному положительному
коэффициенту `a`. Контрольные ночи не используются при его подборе.
Сотни коррелированных измерений не объявляются сотнями независимых ночей.
Формальный вывод, физические границы и ссылки:
[SEASONAL_CALIBRATION.md](https://github.com/WarriorOfTea/LightPollution/blob/52a3604b6603be48e07c4bd0d60a9cf32f0b9f38/docs/SEASONAL_CALIBRATION.md),
[основной перенос](https://github.com/WarriorOfTea/LightPollution/blob/52a3604b6603be48e07c4bd0d60a9cf32f0b9f38/docs/MODEL.md),
[модель наблюдения и Луны](https://github.com/WarriorOfTea/LightPollution/blob/52a3604b6603be48e07c4bd0d60a9cf32f0b9f38/docs/OBSERVATION_MODEL.md).

### Почему не получилось сравнить Петербург

NearNadir: в январе прошло **423/345 600** ячеек, в июле **0/345 600**.
Июльские OffNadir и AllAngle также дали 0/345 600. Общая область на опорной

Это недостаточность пригодных измерений по выбранному строгому QA,
а не измеренный нулевой свет. Сезонная освещённость/снег и условия отбора
важны, но конкретные причины всех пропусков отдельно не установлены.

## 4. Наземное сопоставление: оба результата

Использованы публичные измерения AstMon Johnson V станции UCM,
**40,451111° N, −3,726111° E**. Высота 650 м — заданное приближение.
Для кандидатов требуются Солнце ≤−18°, Луна ≤−5° и одинаково определённое
локальное временное окно. Геометрия не подтверждает отсутствие облаков.

### Более широкая выборка 2015 года: облачность неизвестна

Из 1957 исходных V-измерений двух месяцев в локальные 00:00–04:00
попало 916, геометрию прошли **367/916**, отвергнуто 549/916.
**0/367** имеют подтверждение ясного неба, **367/367** — неизвестную
облачность. Поэтому использован только явный `provisional`-режим.

| Выборка | Ночи / измерения | Bias, mag | MAE, mag | RMSE, mag |
|---|---:|---:|---:|---:|
| Настройка, январь | 8 / 195 | −0,153235 | 0,439824 | 0,515481 |
| Контроль, июль | 8 / 172 | +0,601084 | 0,621859 | 0,992962 |

Знак — модель минус наблюдение; положительное значение означает более тёмный
прогноз. Нельзя приписать все остатки облакам: сезон, спектры, режим освещения,
атмосфера и геометрические приближения здесь независимо не разделены.
[Полные ночные значения и разделение](fit-2015.json).

### Узкие ясные интервалы 2017 года: разметка первичной статьи

В нативном CSV облачных флагов нет. Из **237** геометрических кандидатов
локального окна 23:00–24:00 отобраны **18/237** записей в двух интервалах,
явно обозначенных в авторских Figure 5 и 6 как ясные и безлунные:
19 марта и 19 ноября, 22:00–23:00 UTC. Границы выбраны внутри отмеченных
областей до расчёта остатка; подбор по удачному совпадению не применялся.
Это ручная транскрипция графической разметки с ограниченным временным
разрешением, а не восстановленные исходные машинные QA-флаги.

Первая ночь: **9 измерений**, один параметр масштаба. Вторая: **9 измерений**,
параметры фиксированы. Месяцы и ночи настройки/контроля не пересекаются.

| Величина | Контрольная ночь 19 ноября |
|---|---:|
| Наблюдаемое среднее | 17,881899 V mag/arcsec² |
| Прогноз среднего | 17,746045 V mag/arcsec² |
| Остаток модели | −0,135855 mag |
| MAE и RMSE по единственной контрольной ночи | 0,135855 mag |
| Отношение модельной к наблюдаемой яркости | 1,133292 |

Прогноз примерно на **13,3% ярче** наблюдения. Это одно локальное расхождение,
не «точность модели 13,3%» для произвольного неба. Обучающий остаток нулевой
по построению: один параметр настроен по одному среднему. Он не является
самостоятельным подтверждением физики.

Отдельная JSON-сцена `observe` воспроизводит оба откалиброванных значения
с точностью до 10⁻¹² mag; общий масштаб настроен только на мартовской ночи.
[Происхождение QA и выбранные измерения](astmon-publication-qa.json),
[полный результат](fit-2017.json),
[ноябрьская сцена](scene-2017-11.json),
[её численный выход](observe-2017-11/observation.json).

### Практические границы этого контроля

- Проверен зенит в двух узких часовых интервалах одной станции. Ни цвет,
  ни форма купола, ни видимость глазом/камерой этим не проверены.
- AstMon Johnson V принят как эффективная V; спектральная/нулевая поправка
  к используемой системе независимо не определена. Естественный фон
  21,6 mag/arcsec² и атмосфера заданы, а не восстановлены измерениями.
- Источники пока лежат на сфере `z=0`, а наблюдатель задан на 650 м.
  Это не согласованная DEM-модель мадридского плато. Скалярная калибровка
  способна поглотить часть ошибки, не исправляя форму поля и геометрию.
- Ближние 3 км, вода и источники за границами окна исключены.
  Часы работы ламп, многократное рассеяние, снег и спектры отдельно не учтены.
- Глобальная физическая погрешность **не определена**: недостаточно
  независимых ясных ночей, направлений и измеренных условий.

## 5. Факторы и дальнейшие работы: этап 6

[LIGHT_FACTORS.md](https://github.com/WarriorOfTea/LightPollution/blob/52a3604b6603be48e07c4bd0d60a9cf32f0b9f38/docs/LIGHT_FACTORS.md) и
[редактируемый CSV](https://github.com/WarriorOfTea/LightPollution/blob/52a3604b6603be48e07c4bd0d60a9cf32f0b9f38/docs/LIGHT_FACTORS.csv) содержат **65 факторов**:
влияние, условную силу, опубликованную модель/доступность кода, нужные данные,
сложность интеграции и текущую реализацию. ID F01–F65 устойчивы;
колонка `приоритет_пользователя` намеренно пустая.

Наибольший эффект в разных условиях дают солнечная высота/сумерки,
городские источники и их спектры, Луна, аэрозоли, облака и снег.
В тёмных местах важнее естественный фон; при оценке видимости добавляются
адаптация глаза и блики; для камеры — отклик, оптика, экспозиция и шум.
Это условные оценки, а не универсальный рейтинг для всех точек.

Остаются три направления работ: расширить независимую проверку и её QA;
добавлять выбранные пользователем физические факторы; после согласования
световой сцены построить отдельные количественные модули глаза и камеры.
Отображение на экране потребует собственной проверки. Автосбор атмосферы
и все новые расширения из каталога пока не выполнялись.

## 7. Воспроизведение и файлы

Подготовка среды: `uv sync --locked`. Для точного повторения использовать
имена и хеши в шести `download-manifest.json`. Скопировать выбранный
манифест в соответствующий каталог `data/blackmarble/` как `manifest.json`
до вызова `download_composite()`: иначе каталог NASA может вернуть другую
переработку. Имена папок и API показаны ниже. Токен задаётся существующим
локальным файлом через `BLACKMARBLE_TOKEN_FILE`, без включения его в Git.

```python
from pathlib import Path
from lightpollution.download import download_composite

# Повторить для каждой строки таблицы входов.
# Манифест уже скопирован в папку как manifest.json.
download_composite(
    Path('data/blackmarble/madrid-2017-03'),
    2017, ('h17v04', 'h17v05'), month=3,
)
```

Для Петербурга папки `2025-01`, `2025-07`; тайлы
`h20v02,h21v02,h20v03,h21v03`. Для Мадрида папки `madrid-YYYY-MM`,
тайлы `h17v04,h17v05`. Сырой `AstMon_evol.csv` доступен через
[Zenodo](https://zenodo.org/records/4633001); SHA-256:
`f477416f47487ad918484392fd5c368744d5807c22edf5c0e69ed7450fad88a9`.

```bash
uv run python scripts/run_seasonal_ground.py \
  --astmon scratch/data-search-20261110/AstMon_evol.csv
uv run lightpollution observe \
  --scene artifacts/seasonal-ground-20261110/scene-2017-11.json \
  --output scratch/reproduced-observation
```

Скрипт заново готовит карты и четыре поля; AstMon и HDF5 нужно предварительно
получить отдельно. Небольшие выходные NPZ/CSV, параметры, отчёты и provenance
отслеживаются Git; большие карты не являются приложением к отчёту.
См. также [команды](../../docs/QUICKSTART.md),
[PDF отчёта](implementation-report.pdf), [PDF факторов](https://github.com/WarriorOfTea/LightPollution/blob/52a3604b6603be48e07c4bd0d60a9cf32f0b9f38/artifacts/seasonal-ground-20261110/light-factors.pdf).
